# CodeMate 프로젝트 핵심 방향성 변경 보고서

- 작성일: 2026년 10월 29일
- 프로젝트명: CodeMate
- 작성 목적: 사업 모델 검토 과정과 교수 피드백 이후 확정된 방향을 기록하고, 향후 MVP 개발 기준을 명확히 정의한다.

## 1. 보고서 요약

CodeMate는 처음에 AI가 주니어 개발자의 오류를 분석하고, 해결하기 어려운 문제를 시니어 개발자에게 연결하는 서비스로 기획되었다. 이후 시니어 참여에 대한 보상과 초기 사용자 수 부족 문제를 해결하기 위해 현상금 기반 오류 해결 커뮤니티를 검토했다.

그러나 교수 피드백을 반영하여 프로젝트의 핵심 가치를 다시 검토한 결과, 단발성 오류 해결 경쟁보다 시니어와 주니어 간의 지속적인 관계 형성과 경험 전수가 본 프로젝트에 더 적합하다고 판단했다. 이에 따라 최종 방향을 장기적인 튜터 매칭 및 멘토링 관계 지원 플랫폼으로 확정한다.

최종 서비스 방향은 다음과 같다.

> CodeMate는 시니어 개발자와 주니어 개발자의 만남을 주선하고, 프로젝트 중심의 지속적인 소통과 실무 경험 전수를 지원하는 멘토링 플랫폼이다.

## 2. 최초 기획 방향

### 2.1 서비스 구조

최초 기획은 다음과 같은 오류 해결 흐름을 중심으로 구성되었다.

1. 주니어 개발자가 코드와 오류 로그를 입력한다.
2. AI가 오류 원인과 수정 방법을 분석한다.
3. 사용자가 AI 답변을 적용하고 결과를 검증한다.
4. AI로 해결하지 못한 문제는 시니어 개발자에게 검토를 요청한다.
5. 해결 결과를 저장하여 다시 활용한다.

### 2.2 최초 기획의 목적

- 개발 오류 해결에 필요한 시간을 줄인다.
- AI 답변의 원인과 검증 절차를 함께 제공한다.
- 해결 기록을 개인의 학습 자료로 축적한다.
- AI로 해결하기 어려운 문제를 시니어 개발자의 경험으로 보완한다.

## 3. 최초 기획에서 발견된 문제

### 3.1 시니어 참여 동기 부족

최초 구조에서 주니어는 문제 해결이라는 명확한 이익을 얻지만, 시니어는 자신의 시간과 전문성을 제공해야 했다. 시니어에게 돌아가는 보상이나 장기적인 관계 형성의 가치가 명확하지 않아 충분한 공급자를 확보하기 어렵다는 문제가 제기되었다.

### 3.2 AI 의존의 반복

AI를 사용해 작성한 코드를 충분히 이해하지 못한 상태에서 오류가 발생하고, 해당 오류를 다시 AI에 의존해 해결하면 주니어의 실질적인 역량이 향상되지 않을 가능성이 있다. 단순한 수정 코드 제공은 당장의 문제를 해결할 수 있지만 문제 접근 방식과 설계 판단 능력을 길러주지는 못한다.

### 3.3 단발성 관계

오류 한 건을 해결하면 주니어와 시니어의 연결이 종료되는 구조였다. 이러한 방식으로는 시니어가 가진 설계 철학, 협업 방식, 기술 선택 기준과 같은 경험 기반 지식을 충분히 전달하기 어렵다.

### 3.4 기존 AI 서비스와의 차별성 부족

오류 분석과 수정 코드 제공만으로는 기존 생성형 AI 서비스와 뚜렷하게 구분되기 어렵다. AI API를 연결하는 것만으로 독립적인 플랫폼 가치를 증명하기에는 한계가 있었다.

## 4. 현상금 기반 커뮤니티 검토

### 4.1 현상금 모델을 검토한 이유

시니어 참여 동기를 구체화하고 초기 1대1 매칭에 필요한 사용자 규모 문제를 완화하기 위해 현상금 기반 오류 해결 커뮤니티를 대안으로 검토했다.

검토한 흐름은 다음과 같다.

1. 주니어가 오류 게시글과 현상금을 등록한다.
2. 여러 개발자가 해결안을 제출한다.
3. 질문자가 해결안을 직접 테스트한다.
4. 정상 작동한 답변을 채택한다.
5. 채택된 답변자가 현상금을 받는다.

### 4.2 기대했던 장점

- 시니어 또는 숙련 개발자에게 직접적인 참여 동기를 제공할 수 있다.
- 실시간 1대1 매칭 없이 비동기 방식으로 운영할 수 있다.
- 여러 답변자가 해결안을 제시해 답변 품질을 비교할 수 있다.
- 해결된 질문과 답변을 검색 가능한 개발 지식으로 축적할 수 있다.

### 4.3 현상금 모델의 한계

- 문제를 가장 빨리 해결하는 경쟁에 집중될 수 있다.
- 시니어와 주니어의 관계가 답변 채택 이후 종료될 가능성이 높다.
- 문제 해결 결과는 얻을 수 있지만 주니어의 장기적인 성장까지 보장하기 어렵다.
- 답변 복제, 미채택, 오답, 현상금 분쟁을 관리하는 기능이 필요하다.
- 실제 현금을 사용할 경우 결제, 환불, 정산과 운영 정책이 추가되어 MVP 범위가 커진다.
- 경험 전수라는 프로젝트의 가치보다 거래와 경쟁이 서비스의 중심으로 인식될 수 있다.

## 5. 교수 피드백 이후 재검토

교수 피드백을 반영하여 프로젝트가 해결하려는 본질적인 문제가 무엇인지 다시 검토했다. 핵심 질문은 단순히 오류를 빠르게 해결하는 것인지, 또는 주니어 개발자가 시니어의 경험을 통해 실질적으로 성장하도록 돕는 것인지였다.

논의 결과, 본 프로젝트가 제공해야 하는 핵심 가치는 개별 오류의 외주형 해결보다 다음 항목에 있다고 판단했다.

- 시니어와 주니어가 서로 만날 수 있는 접점을 제공한다.
- 단발성 답변을 넘어 지속적인 멘토·멘티 관계를 만든다.
- 실제 프로젝트를 중심으로 실무 경험과 판단 기준을 전수한다.
- 주니어가 스스로 문제를 해결할 수 있는 역량을 기르도록 돕는다.
- AI는 사람을 대체하지 않고 멘토링을 정리하고 보조한다.

따라서 현상금 모델은 참여 보상 문제에 대한 하나의 해결책이지만, 프로젝트가 지향하는 인간적인 교류와 기술 전승을 충분히 구현하지 못한다고 결론 내렸다.

## 6. 최종 확정 방향

### 6.1 서비스 정의

CodeMate는 AI가 오류를 대신 해결하거나 현상금을 걸고 답변을 경쟁시키는 서비스가 아니다. 시니어와 주니어 개발자가 프로필, 개발 커뮤니티, 프로젝트·동아리 모집, 커피챗과 멘토링을 통해 지속적으로 연결되는 개발자 성장 플랫폼으로 운영한다.

### 6.2 핵심 이용 흐름

1. 사용자가 공개 범위와 기술 스택, 프로젝트·포트폴리오, 관심 분야를 포함한 프로필을 작성한다.
2. 관리자가 시니어의 경력과 포트폴리오를 확인해 가입을 승인한다.
3. 사용자는 개발·자유·건의 게시판에서 질문, 정보, 프로젝트·동아리 모집 정보를 교류한다.
4. 주니어는 관심 있는 시니어, 개인 또는 동아리를 팔로우하고 프로젝트·커피챗·멘토링을 요청한다.
5. 검증된 시니어 또는 모집 주체가 요청을 수락하거나 거절하고, 양측은 프로젝트와 학습 과정을 공유한다.
6. 활동 종료 후 후기와 상호 평가를 남기며, 평점·평가 사유·신고 이력은 관리자만 열람한다.

### 6.3 시니어 참여와 권한 원칙

초기 MVP는 금전적 보상, 현상금, 결제·정산을 전제로 하지 않는다. 시니어의 전문성 공개, 멘토링·피드백 기여 기록, 커뮤니티 평판과 네트워크 형성을 비금전적 참여 가치로 제공한다.

검증된 시니어는 모집글 작성·관리, 동아리 운영, 커피챗 요청 수락·거절, 활동 후기 작성 권한을 가진다. 이 권한은 콘텐츠와 관계 관리에 한정하며, 다른 사용자의 비공개 평가·개인정보·관리자 기능에는 접근할 수 없다.

## 7. 프로필과 관계 기능

### 7.1 공개 범위와 어필 요소

- 사용자는 프로필을 전체 공개, 회원 공개, 비공개 중에서 선택한다. 비공개 프로필은 본인과 관리자만 열람한다.
- 주니어는 기술 스택, 프로젝트·포트폴리오, 관심 분야, 해결 기록, 자기소개로 성장 과정과 강점을 보여 준다.
- 시니어는 검증된 경력, 전문 분야, 멘토링·피드백 이력, 모집 동아리·프로젝트 정보를 공개할 수 있다.
- 프로필 하트(응원)는 공개 지표로 제공하고, 개인·동아리 팔로우는 새 활동과 모집글을 받아보기 위한 관계 기능으로 제공한다.

### 7.2 모집·커피챗·후기·평가

- 동아리 또는 프로젝트 모집글에는 소개, 모집 분야, 기간, 정원, 지원 방법을 등록한다.
- 주니어와 시니어 모두 커피챗을 요청할 수 있으며, 주니어는 프로젝트·기술 스택·해결 기록을 공유해 모집 활동에 지원한다.
- 활동 및 커피챗 후기는 공개 여부를 작성 시 선택하며, 작성자·대상자·관리자 신고 절차를 연결한다.
- 상호 평가는 활동 종료 후 진행한다. 평점, 평가 사유, 신고 이력은 관리자 전용으로 저장하고, 상호 평가가 모두 끝나거나 평가 기간이 종료된 뒤에만 관리자에게 공개한다.

## 8. 3단계 커뮤니티: 카테고리형 자유게시판

3단계는 수익성 기능이 없는 카테고리형 자유게시판이다. 현상금, 결제·정산, 답변 채택과 답변 경쟁은 MVP 범위에서 제외한다.

| 게시판 | 목적 | 초기 기능 |
| --- | --- | --- |
| 개발 게시판 | 기술 질문, 지식 공유, 토론 | 프론트엔드·백엔드·모바일·데이터/AI·인프라/DevOps·협업/회고 카테고리 |
| 자유 게시판 | 개발 일상, 스터디, 행사, 팀원·동아리 모집 | 게시글·댓글·카테고리 필터·검색 |
| 건의 게시판 | 기능 제안, 불편 사항, 운영 건의 | 관리자 답변·처리 상태·신고 |

공통 기능은 게시글 작성·조회·수정·삭제, 댓글, 카테고리 필터, 검색, 신고, 관리자 콘텐츠 관리로 제한한다. 좋아요·추천은 초기 사용자 검증 후 도입 여부를 결정한다.

## 9. AI 역할 재정의

AI는 문제 해결의 주체가 아니라 멘토링과 커뮤니티 활동을 보조하는 기능으로 제한한다. 향후 후보는 멘토링 대화 요약, 학습·진행 기록 정리, 피드백 핵심 항목 분류, 다음 목표 초안, 관심 기술 기반 매칭 보조, 반복 질문·학습 어려움 분석이다.

AI가 수정 코드를 즉시 제공하는 기능은 핵심 MVP에서 제외한다.

## 10. 수정된 MVP 범위와 개발 우선순위

### 1단계: 기존 인증과 권한 안정화

- 주니어·시니어·관리자 권한 검증
- 시니어 승인 흐름과 사용자별 데이터 접근 제한

### 2단계: 프로필 고도화

- 공개 범위, 포트폴리오·프로젝트, 기술 스택, 관심 분야, 어필 요소와 제한 CSS 꾸미기
- 시니어 전문 분야·경력·활동 가능 시간 및 주니어 프로젝트 정보

### 3단계: 카테고리형 게시판

- 개발·자유·건의 게시판, 카테고리, 댓글, 검색, 신고·관리 기능
- 현상금·결제·답변 채택은 구현하지 않음

### 4단계: 관계와 소통

- 개인·동아리 팔로우, 모집글, 커피챗 요청, 후기, 관리자 전용 상호 평가
- 멘토링 신청·수락·거절, 매칭 상태 및 지속적인 활동 기록

### 5단계: 관리자와 사용자 테스트

- 회원·콘텐츠·신고 관리
- 실제 시니어·주니어 대상 사용성 평가와 관계 지속 의향·만족도 조사

### MVP 제외 기능

- 현상금 등록·지급, 실제 결제·정산, 답변 경쟁·채택
- AI 자동 오류 수정, 실시간 화상 통화, 복잡한 추천 알고리즘, GitHub 자동 연동

## 11. 기존 구현물 처리 방안

현재 구현된 로그인, 역할 구분, 시니어 승인, 관리자 권한과 공통 UI는 유지한다. 기존 오류 게시글 기능은 개발 게시판의 기술 질문 또는 프로젝트 이슈·해결 기록으로 점진 전환한다.

| 기존 기능 | 변경 후 활용 방식 |
| --- | --- |
| 오류 등록 | 개발 게시판의 기술 질문 또는 프로젝트 이슈 |
| 해결 기록 | 개인 프로필 및 활동 기록 |
| 해결 상태 | 질문 대기·피드백 완료·종료 상태 |
| 시니어 검토 | 멘토링 또는 커피챗 피드백 |
| 관리자 삭제 | 게시글·댓글·신고 콘텐츠 관리 |

## 12. 성과 지표

현상금 모델의 답변 수·채택률 대신 프로필 완성, 커뮤니티 참여, 관계 형성과 활동 지속성을 측정한다.

| 평가 항목 | 측정 방법 | 초기 목표 |
| --- | --- | ---: |
| 프로필 완성률 | 가입 후 프로필을 완성한 사용자 비율 | 60% 이상 |
| 게시판 첫 활동 완료율 | 가입 후 첫 게시글 또는 댓글 작성 비율 | 50% 이상 |
| 멘토링·커피챗 요청 수락률 | 전체 요청 중 수락 비율 | 40% 이상 |
| 첫 소통 완료율 | 매칭 후 첫 질문 또는 피드백 작성 비율 | 70% 이상 |
| 2주 이상 관계 유지율 | 2주 이상 활동한 관계 비율 | 50% 이상 |
| 멘토 재참여 의향 | 시니어 대상 설문 | 60% 이상 |
| 멘티 만족도 | 5점 척도 설문 | 평균 4점 이상 |

초기 목표는 MVP 검증을 위한 잠정 기준이며 실제 사용자 테스트 후 조정한다.

## 13. 최종 결론

CodeMate는 AI 오류 해결, 현상금 기반 오류 해결 커뮤니티, 시니어·주니어 지속형 튜터 매칭을 차례로 검토했다. 최종적으로는 단발성 해결이나 경쟁보다 개발자 간 관계 형성, 경험 전수, 커뮤니티 활동을 중심에 둔다.

> CodeMate는 시니어와 주니어 개발자가 프로필·커뮤니티·모집·커피챗·멘토링을 통해 실제 프로젝트를 함께 논의하고 장기적으로 성장하도록 지원하는 개발자 성장 플랫폼이다.
