# 사업계획서 초안 정리

## 교수님 강조사항

- 오늘 만드는 것은 완성본이 아니라 사업 아이템의 전체 초안이다.
- 서비스의 문제, 해결 방식, 현재 구현 상태, 향후 실행 계획이 하나의 문서 안에서 자연스럽게 연결되어야 한다.
- 정부지원사업계획서의 기본 구조를 따른다.

  1. 문제인식
  2. 실현가능성
  3. 사업화 방향
  4. 팀 및 실행계획

## 사업계획서에서 보여줘야 할 핵심

- 필요성: 어떤 문제를 왜 해결해야 하는지 명확해야 한다.
- 가능성: 제시한 해결 방식이 현실적으로 구현·운영 가능한지 보여줘야 한다.
- 실행력: 팀이 실제로 개발하고 사용자 검증까지 추진할 역량과 계획이 있는지 보여줘야 한다.

## 내용 작성 원칙

- 사업 소개는 긴 설명보다 서비스 가치를 담은 한 문장으로 먼저 제시한다.
- 조사 결과는 숫자만 나열하지 않고, “그래서 이 문제가 실제로 존재하며 DebugMate가 필요하다”는 주장과 연결한다.
- 모든 내용은 다음 세 가지로 구분한다.

| 구분 | 작성 내용 |
| --- | --- |
| 확인한 사실 | 설문, 인터뷰, 시장 자료, 직접 조사 등 근거가 있는 내용 |
| 현재 상태 | 기획 완료 범위, 구현된 MVP, 현재 팀이 보유한 기술과 역량 |
| 향후 계획 | 사용자 검증, 추가 개발, 고객 확보, 운영 및 확장 계획 |

## 다음 주 과제: 사업계획서 초안 구성

1. **문제인식**  
   주니어 개발자가 겪는 성장·소통·멘토 탐색의 어려움과 기존 AI·커뮤니티의 한계를 설명한다.

2. **해결방법**  
   DebugMate가 프로필, 개발자 커뮤니티, 모집, 커피챗, 멘토링을 통해 어떻게 연결과 경험 전수를 지원하는지 제시한다.

3. **MVP 현황**  
   현재 구현된 회원가입·로그인·역할 구분·시니어 승인·오류 기록 관리·프로필 기능을 정리하고, 아직 구현 전인 기능도 구분한다.

4. **시장·경쟁**  
   기존 AI 도구, 일반 개발 커뮤니티, 멘토링 플랫폼과 비교해 DebugMate의 차별점인 “지속적인 관계 형성과 성장 기록”을 강조한다.

5. **사업화 실행**  
   프로필 고도화 → 게시판 → 팔로우·모집·커피챗·멘토링 순으로 개발하고, 사용자 인터뷰와 테스트를 통해 검증하는 계획을 작성한다.

6. **팀 구성**  
   팀원별 담당 역할, 현재 개발 역량, 부족한 역량의 보완 계획을 제시한다.

7. **아이템 개요**  
   한 문장 소개, 대상 사용자, 핵심 문제, 해결 방식, 핵심 기능, 기대 효과를 요약한다.

## 사업 한 문장 예시

> DebugMate는 주니어와 시니어 개발자가 프로필, 커뮤니티, 모집, 커피챗, 멘토링을 통해 연결되고 실제 프로젝트 경험을 나누며 함께 성장하도록 돕는 개발자 성장 플랫폼이다.
